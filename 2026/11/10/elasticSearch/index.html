elasticSearch(ES)

一.什么是ES

elastic Search也就是es，是一个强大的开源、分布式、RESTful 风格的全文搜索引擎，介于应用和数据之间，只要将数据写入es,应用就可以通过一些关键词搜索到数据，效果就和百度类似

二.ES的底层存储与核心数据结构

ES的底层是一套用Java编写的开源核心库 – Lucene 。ES是在Lucene外面包了一层分布式架构的”壳”，在底层设计了多套极其精巧的数据结构

  • 倒叙索引：这是ES的核心数据结构。把内容拆解成词，通过词来找文档，我们将这堆排好序的词项，称为Term Dictionary，而词项对应的文档 id 等信息的集合，就叫 Posting List。它们共同构成了一个用于搜索的数据结构，它就是倒排索引(Inverted Index)

Posting List 还包含词频和词项在文本里的偏移量等信息

  • Term Index：由于企业级数据的词典往往极其庞大，无法全部装入内存。由于词项和词项之间有些前缀是一致的，基于这个原理，我们可以将 Term Dictionary 的部分词项提取出来，用这些 词项 的前缀信息，构建出一个精简的目录树。目录树的节点中存放这些词项在磁盘中的偏移量，也就是指向磁盘中的位置。这个目录树结构，体积小，适合放内存中，它就是所谓的 Term Index。可以用它来加速搜索

  • Stored Fields：这是一种行式存储结构。倒排索引的任务仅限于找出符合条件的文档 ID，而 Stored Fields 则专门用于保存文档的原始原文数据（如完整的 JSON 结构），以便在搜索命中后将详细信息展示给客户端

  • Doc Values：构造一个列式存储结构，将散落在各个文档的某个字段，集中存放，当我们想对某个字段排序的时候，就只需要将这些集中存放的字段一次性读取出来，就能做到针对性地进行排序。这个列式存储结构，就是所谓的 Doc Values

  • Segment(数据段）：这些结构共同组成了一个复合文件，也就是所谓的”segment“, 它是一个具备完整搜索功能的最小单元

三.分布式集群和架构特性

单机的Lucene算力有限，ES的分布式外壳有着无限扩展空间

  • 高性能：对写入 lucene 的数据进行分类,然后根据 Index Name 新增 lucene 的数量，将不同类数据写入到不同的 lucene 中，读取数据时，根据需要搜索不同的 Index Name.但单个 Index Name 内数据依然可能过多，于是可以将单个 Index Name 的同类数据，拆成好几份，每份是一个 shard 分片，每个 shard 分片本质上就是一个独立的 lucene 库。这样我们就可以将读写操作分摊到多个 分片 中去，大大降低了争抢，提升了系统性能

  • **高扩展性:**将 分片 分散部署在多台机器上，这每一台机器，就是一个 Node。我们可以通过增加 Node 缓解机器 cpu 过高带来的性能问题

  • **高可用：利用副本（Replica）机制，主分片的数据会自动同步至其他节点。即使个别服务器发生物理宕机，集群也能瞬间切换，不影响整体数据完整性和读写服务。

  • 去中心化：将这不同功能拆开，给集群里的 Node 赋予角色身份，不同的角色负责不同的功能。比如负责管理集群的，叫主节点(Master Node)， 负责存储管理数据的，叫数据节点(Data Node)， 负责接受客户端搜索查询请求的叫协调节点(Coordinate Node)。集群规模小的时候，一个 Node 可以同时充当多个角色，随着集群规模变大，可以让一个 Node 一个角色

  • Node角色分化：将这不同功能拆开，给集群里的 Node 赋予角色身份，不同的角色负责不同的功能。比如负责管理集群的，叫主节点(Master Node)， 负责存储管理数据的，叫数据节点(Data Node)， 负责接受客户端搜索查询请求的叫协调节点(Coordinate Node)。集群规模小的时候，一个 Node 可以同时充当多个角色，随着集群规模变大，可以让一个 Node 一个角色

四.核心工作流程

ES的写入流程：

1.协调节点接受数据，通过Hash路由算法锁定目标主分片位置
2.主分片所在节点将数据写入内存缓冲区，并同步记录至容灾文件
3.默认每间隔1s触发Refresh操作，将缓冲区数据封装为Segment并写入OS Cacher,此时数据即可对外提供搜索
4.后台根据阈值出发Flush操作，强制将OS Cache中的数据落盘至物理磁盘，并重置清理Translog,确保数据最终的安全固化

ES的搜索流程（Query-Then-Fetch)

  • 查询阶段:协调节点将搜索请求扇出给目标索引的所有分片。各分片在本地独立执行匹配计算，完成后向协调节点返回匹配文档的ID列表和相关度打分
  • 获取阶段：协调节点在本地内存中对汇聚来的全局文档ID按分数重新进行合并排序。确定最终需返回的TOP N 文档后，向对应的目标分片发起点对点的数据抓取请求，提取完整文档信息后组装返回给客户端

五.总结

Elasticsearch 并不是传统意义上的数据库，而是一个以空间换时间、将内存与并发价值压榨到极致的分布式检索引擎

它的本质是在 Lucene 这个检索核心之外，精心封装了一层高度可扩展的分布式架构“壳”。在微观底层，它依靠“倒排索引”与“驻留内存的 Term Index字典树”实现了对海量非结构化数据的毫秒级精准打击；依靠“列式 Doc Values”打破了倒排结构无法高效统计的魔咒。而在宏观架构上，它通过精妙的分片路由与多副本机制，轻松跨越了单机硬件的物理瓶颈与单点故障风险
